# «Тыныс»: два будущих рудника

Энергетик проверяет, какое ограничение сети выдержит рудник, как изменятся
производство и запасы и что придётся восстанавливать после события.
Эксперимент не меняет уставки действующего стенда.

## Запуск и демонстрация

Запустите весь стенд командой `make tynys` по корневому README, затем откройте
`http://localhost:8095/futures.html`.

1. Оставьте запрос «снизить лимит сети на 80 МВт на 4 часа». Нажмите
   **Проверить обещание**. Сервис зафиксирует состояние поля и текущие сценарии.
   Расчёт выполняется в фоне; прогресс отображается на экране.
2. В паспорте прочитайте результат и причины. Снижение лимита с 260 до 180 МВт
   не равно фактическому снижению потребления на 80 МВт: последнее показано отдельно.
3. Перематывайте общий час: две сцены показывают обычные правила V1 и планировщик
   V2 на одной погоде, руде, оборудовании и ограничениях. Камеры синхронизированы.
4. Перейдите к участку **восстановление**. Сравните медь, заряд флота и BESS,
   дополнительное потребление и остаточный долг относительно контрольного V2.
5. Добавьте два часа, штиль или отказ накопителя и пересчитайте.
   **Найти предел** проверяет набор длительностей. Для каждого нового расчёта
   фиксируется новый текущий снимок; номер часа и исходные условия видны в отчёте.
6. Скачайте JSON: это рассчитанные ряды, параметры, исходное состояние и причины.
   **Отменить** прекращает расчёт; сброс экрана не воздействует на производство.

## Четыре функции

**Два будущих.** Обычное управление V1 и MPC V2 получают независимые копии одного
состояния и одинаковые внешние ряды. Одинаковы мощности оборудования. Различаются
решения о помоле, сортировке руды, заряде и использовании накопителя. Преимущество
V2 не задано заранее; сравнивайте также его неудачные сценарии.

Для интерактивных экспериментов MPC пересчитывается каждый час с горизонтом
12 часов и фиксированным бюджетом 16 узлов MILP. Основной координатор стенда
сохраняет горизонт 24 часа. В отчёте указаны параметры решателя, число шагов
с ограничением поиска и переходы на запасное правило V1.

**Проверяемое обещание.** Статус относится к полному запросу и заданным допускам.
Если меньший запрос проверен и выполним, он показывается отдельной альтернативой.
Её нельзя путать с успешным выполнением исходного запроса. Нехватка мощности,
простои, потери производства и невосстановленные запасы не скрываются.

**Цена помощи завтра.** Третий прогон — V2 без добавленного ограничения сети,
но с теми же погодой и сбоями. Относительно него считаются долг по меди,
остаткам энергии и дополнительное потребление во время восстановления.
24–48 часов — конечное окно проверки, не прогноз на бесконечное будущее.

**Найди предел.** Отчёт содержит именно проверенные длительности. Успех между
точками не предполагается, вероятность успеха не выдумывается. Дополнительные
сбои задаются до прогона. Это сценарный эксперимент, не оценка всех возможных аварий.

## Данные и платформа

Браузер пишет строку запроса в `kz.tynys:future-request`. Сервис
`tynys-futures` читает `site.state_json` и `scenario`, проверяет совпадение
ревизии и запускает расчёт. Результат возвращается через MQTT
`telemetry/future-result` → Ditto → браузер.

В Compose для отчётов до 66 часов установлен предел размера Thing 1 МБ и
кадра обмена сервисов Ditto 2 МБ. Сам сервис отклоняет отчёт больше 800 КБ.

Живое поле продолжает работу, пока отчёт хранит замороженный снимок.
При потере связи интерфейс сообщает об этом. Старый отчёт не становится
расчётом новых условий. Самосвалы и потоки внутри часа анимированы схематично.

Все ограничения исходной модели, источники параметров и допущения сохраняются:
см. корневой `SUBMISSION.md`. «Выполнимо» означает, что проверка пройдена в
данной модели и сценарии. Это не гарантия для реального промышленного оборудования.

## Проверка

Локальные модельные тесты:

```bash
pip install -r team/tynys/requirements.txt
python -m unittest discover -s team/tynys/tests -v
```

После запуска полного стенда:

```bash
python team/tynys/scripts/check_futures.py
```

Сквозная проверка отправляет запрос через прокси браузера, получает вычисленный
результат из Ditto и сохраняет `futures-e2e-report.json`. Отдельный workflow
`Tynys two futures` проверяет модель, сервис и этот путь в Ubuntu 24.04.
